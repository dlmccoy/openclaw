# Terminal settlement integration plan (not implemented)

The accompanying test is an executable model, not an integrated API or evidence of durable snapshots. Do not ship it as production behavior. The existing transcript and lifecycle owners have independent paths; installing a barrier at only one would give false settlement guarantees.

1. Bind an opaque occurrence/generation to the host admission in `src/agents/embedded-agent-runner/run/attempt-transcript-lifecycle-prepare.ts`, alongside the existing `withOwnedTranscriptWrite` capability. Define replacement, abort, and disposal in that owner, not by run ID. Determine whether the existing transcript admission and locks can provide the barrier before introducing another owner.
2. Account for every admitted write before sealing: `attempt-prompt-phase.ts` wraps writes in `withOwnedTranscriptWrite` and `withSessionManagerAppend`; `attempt-session-prepare.ts` includes replay and other writes; `attempt-finalize.ts` includes context-engine maintenance/rewrite and bootstrap append. Audit all other users of these session-manager boundaries, including detached work, before asserting completeness. Accepted asynchronous writes must settle on success and failure; never release on cancellation notification alone. Specify failure/unknown outcomes and avoid deadlock on reentrant writes.
3. In `attempt-finalize.ts`, after the eligible writes and context-engine finalization settle, capture the current attempt's message using the existing `transcriptLeafId` boundary before `captureAgentTerminalSnapshot` and `runAgentEndSideEffectsAsync`. Reject replaced generations at the point of capture. Preserve refresh, detached, revision, and suppressed-write branches. The existing `AgentTerminalSnapshot` is content-free attempt classification, not a durable transcript snapshot.
4. Trace the lifecycle producer through agent events and establish an explicit settlement handoff to `src/gateway/server-chat-lifecycle-publication.ts` before `persistence.then` broadcasts `sessions.changed`; preserve its error fallback. Reconcile `src/gateway/server-chat-transcript-publication.ts` `holdTerminal`, `retireTranscript`, and `drain` with the same occurrence; do not substitute gateway delivery completion for transcript write settlement. Audit all other terminal consumers and cleanup paths before cutover.
5. Add boundary tests with actual session manager and lifecycle publication: delayed accepted write blocks terminal publication; write rejection is surfaced without hanging; replacement with reused run ID cannot publish old data; abort does not imply writer settlement; no writes admitted after seal; repeat release is harmless; refresh and detached paths remain correct. Exercise existing gateway transcript and lifecycle suites and a real isolated gateway flow. The model test only establishes two local ordering properties and uses no production code.

Open decisions: ownership lifetime across retries and process restart; whether snapshot is immutable material or a durable anchor; behavior on unknown write outcome and restart recovery; coverage of external/context-engine writers. These must be resolved before a safe integration; current evidence does not establish a complete write inventory or durable recovery protocol.

## Storage, resumption, and publication work still required

- `src/infra/agent-run-terminal-writes.ts` `drainAgentRunTerminalWrites` uses `Promise.allSettled` and returns no durable success receipt. Trace its callers in auto-reply, cron, embedded runtime, talk, and command execution. Controller settlement alone is explicitly insufficient (`src/gateway/server.talk-consult-history.test.ts`, `waitForDispatchEnd`). The host must define whether any rejected or ambiguous write disqualifies closure, persist a generation-bound settlement fact only after all eligible producers stop admitting work, and recover safely after process death.
- `src/config/sessions/session-transcript-event.ts` routes worker writes through `session-message-rewrite.worker.ts`; `session-accessor.sqlite-transcript-write-guard.ts` checks owner/revision only when supplied. Audit message append, event append, rewrite, branch replacement, compaction, imports, cold-storage and maintenance paths at their synchronous database transaction point; an in-process model is not an exhaustive fence. Never insert async waits inside a SQLite transaction. Memory/incognito and unsupported backends must remain unknown until individually supported.
- `src/config/sessions/session-accessor.sqlite-lifecycle.ts` resets under `runExclusiveSqliteSessionWrite` and changes entries in a transaction. The delete owner spans `session-accessor.sqlite-deletion.ts` and `session-accessor.sqlite-deletion-plan.ts`; `session-cold-storage.ts` restores archived transcript state. Bind deletion/reset/restore and ACP `src/agents/subagents/spawn/acp-spawn.ts` resume to the same generation authority, invalidating any pending snapshot before the publication effect. A cold archive is storage placement, not proof of terminal status.
- Define a host-owned closed snapshot operation against the session worker and durable database identity. Capture bounded content and the exact eligible generation at a consistent read point, not from raw archive enumeration; ensure actual write owners cannot mutate it after sealing. Separately define deletion/revocation semantics through the downstream publish effect: an external sink cannot participate in a local SQLite transaction by assumption. A transactional outbox or another explicitly reviewed coordination protocol may be necessary; prove crash/retry and revoked-before-publish cases rather than claiming atomicity across systems.
- Add owner-boundary integration tests for explicit terminal and archive eligibility; live, deleted, unknown and resumed exclusions; write/delete/reset/restore/resume racing both snapshot and publication; process restart, duplicate identity, uncertain writes, and retry. The accompanying toy model simulates only ordering and cannot validate any of these real storage or concurrency guarantees.
